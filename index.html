为什么是 EA

一个人的判断，成为一群人的起点。

测试工程师留下失效条件，设计工程师读到同一份证据，就能用另一套专业知识解释它。当不同专长的人能复查、借鉴彼此的判断，团队就有机会解决单个专家解不开的问题。

过去 · 没有 EA
现在 · 用 EA
✕ 工程信息散落在邮件、Excel 与各系统之间
✓以 Case 为单位统一收拢，全流程留痕可追溯
✕ 问题靠个人经验，debug 难以复用
✓怀疑方向 → 验证任务 → 证据与结论，保留每条分析路径
✕ 任务分派口头化，进度与归属不透明
✓我负责 / 我分派分开跟进，脑图、任务视图与甘特图协同查看
✕ 结案之后，记录质量与整改进展难以跟进
✓Case 得分与整改清单，从发现缺口到补齐记录
闭环管理 · CLOSED LOOP

记录问题

把问题现象、背景与影响范围写进 Case，明确产品、Owner、L0–L3 等级与紧急度，让协作从同一份事实开始。

01

建立 Case · 先对齐事实

以「DDR5 X-die CP1 yield drop @Site A」为例，记录异常现象、物料与测试条件，说明为什么发起、影响什么，再确定协作人员。
产品问题建立 Case，日常事务使用自由任务
等级 L0–L3 与紧急度分别表达影响和优先程度
02

拆解思路 · 分派验证

先列怀疑方向，再挂载具体执行任务。把 Pattern、工艺与物理失效等路径分派给对应工程师，任务接受、执行与结果都有归属。
脑图看路径，任务视图看分工，甘特图看时间
从「我的任务」接受分派、进入 Workspace
03

保留证据 · 确认根因

在 Workspace 中记录分析过程、结论与附件，区分有效和无效路径。确认根因归属后进入验证，按需要向相关产品发起 Fanout。
结论与过程证据保存在原 Case / 任务文档
关联或标记重复 Case，不自动合并原始数据
04

验证结案 · 持续整改

验证完成后提交结案结论，保留验证起止时间。已结案 Case 若需补充验证，可由监管范围内的管理者退回整改，结果仍回到原文档。
新发起的 Case 整改固定 24 小时期限
要求、实质修改与提交快照持续留痕
协作分析 · 思路与执行分开，路径与证据相连

不只知道谁在做，
更知道为什么做。

用「怀疑方向 + 执行任务」组织分析树。保留已经排除的路径，也看清下一步该验证什么；多人协作，不再丢失分析上下文。

✓三种视图，同一份任务　思维导图看路径、任务视图看分工、甘特图看实际执行时间。
✓按需聚焦　全局、未完成、有效路径、只看我的，让复杂分析树变得可读。
✓有据可查　过程、结论和附件留在 Workspace；记录创建、接受开始与完成节点。
✓直接用于评审　演示模式沿节点讲解，少一次整理，多一份完整上下文。

CASE 得分 · 六维记录完整度

每一个分数，
都能找到记录依据。

不只看“做完了多少”，也看“留下了什么”。从背景、过程到证据与结论，六个维度帮助发现记录缺口；在详情中展开雷达图，直接查看权重与计算依据。

案件背景 20%
分析过程 20%
证据记录 15%
结论沉淀 20%
任务闭环 15%
分工明确 10%
✓同一套口径　详情、全部 Case 列表和热门 / 关注度排行读取同一得分。
✓随记录更新　保存过程、结论或附件后重新计算，缺失项不补造分数。

当前为原型试算，反映记录完整度，不代表结论正确性或绩效评价。正式评分标准待业务确认。

监管整改 · 让反馈回到原文档

结案不是记录的终点。

从「我的任务 → 我发起的整改」跟进本人发起的 Case 与 Case 任务整改。要求、期限、修改和结果，始终有迹可循。

EA V1.0.9 / 我发起的整改
✓明确责任与期限　已结案 Case 可按监管范围退回；新发起的 Case 整改固定为提交后 24 小时。
✓三种状态，一份清单　整改中、已整改、超期互不重复，点击统计卡片筛选，标题直达原文档。
✓修改与结果可追溯　保存实际修改才计入处理中；提交保留前后快照，查看反馈不改变业务状态。
提出要求→修改原文档→提交反馈

“已整改”表示已提交反馈，不等于管理者验收。结案审批独立进行；Case 内任务沿用自身期限规则。提醒为页面内计算，非后台消息推送。

协作连接 · 找到人，也保留完整上下文

关键参与者一眼可见，
协作名单不遗漏。

全部 Case 列表在 Owner 后呈现最多两位核心参与者，帮助快速识别当前协作关系。需要沟通时，管理者可在 Case 详情体验 HEMS 建群与参与人补充流程。

✓核心参与者　结合当前 Case 的任务与记录识别协作人员，不作为绩效排名。
✓按完整名单建群　首次包含操作管理者、Owner 与完整参与人，不受列表两人展示上限影响。
✓后续增量补充　只补充新增或上次失败的人员，无需重复加入已有成员。

HEMS 建群仅向主管、总监、VP 展示入口。当前为本地群组模拟，尚未连接 HEMS，不会实际建群或发送邀请。

Engineer

  • 思维导图 / 任务视图 / 甘特图
  • 根因归属、Fanout 与验证起止记录
  • 六维 Case 得分，发现记录缺口
Manager

部门管理者

从产品与 Case 总览发现改进方向，在监管范围内持续跟进整改。

  • 从万能看板的产品视角定位高耗时 Case
  • 我发起的整改，追踪期限和提交反馈

技能中心 · 从入口走进工作区
